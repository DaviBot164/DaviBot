# Kitsune Core — გასუფთავებული Discord ბოტი

ატვირთული Akane პროექტის ცალკე გასუფთავებული ვერსია. შენარჩუნებულია ატვირთულ კოდში არსებული Kitsune სახელწოდება, სერვერის პარამეტრების ფორმატი, channel/role ID-ები და PostgreSQL მონაცემებთან თავსებადობა. ბოტის ანგარიშის სახელი გაშვებისას ავტომატურად აღარ იცვლება.

## რა დარჩა

- მისალმება არსებული ბანერით და წესების/ვერიფიკაციის/ფრაქციის ბმულებით.
- Bloxlink-ის ვერიფიკაციის ინსტრუქცია; თავად Roblox ვერიფიკაციას ისევ Bloxlink ასრულებს.
- წესები, გზამკვლევი, როლების/რანკების ინსტრუქცია და setup.
- მოდერაცია, Guardian AutoMod, მოქმედებების ისტორია და ლოგები; emergency დაცვაც შენარჩუნებულია, რადგან მოდერაციის ნაწილია.
- ტიკეტის შექმნა, დახურვა, ხელახლა გახსნა და ლოგები.
- შეტყობინებების XP, cooldown, ლეველები, ფრაქციები, რანკები, ავტომატური დაწინაურება და ხელით მართვა.
- მარტივი პროფილი: ლეველი, XP, ფრაქცია, რანკი და XP-დასაშვები შეტყობინებების რაოდენობა; ასევე leaderboard და corps.
- help, ping, avatar და announce; არსებული announce-ის ვარიანტები შენარჩუნებულია.

დარჩენილია 30 ბრძანება. მომხმარებლისა და staff-ის ბრძანებები help-ში უფლებების მიხედვით გამოჩნდება.

## რა მოიხსნა

საუბრები/AI/ცოდნის ბაზა და სწავლა, Kitsune hub, ისტორიები და თამაშები, control HTTP სერვერი, მატჩები, მისიები/quest, daily ჯილდოები და streak, achievements, titles, legacy და trials. მათთვის განკუთვნილი ძველი ტესტები, რეპორტები და გაუყენებელი მოდულებიც მოცილებულია. არც help და არც ახალი setup გვერდები მათ აღარ სთავაზობს.

უმაღლესი რანკები კვლავ staff-ის დასანიშნია; ავტომატური ლეველი მათ არ გასცემს. უკვე ჩართული დამატებითი რანკები (extended ranks) არ იშლება.

## დაყენება Windows-ზე

1. ZIP გაშალე **ახალ ცალკე საქაღალდეში** და VS Code-ით გახსენი `Kitsune-Core`. ძველ პროექტს ჯერ ნუ წაშლი. ძველ საქაღალდეში მხოლოდ გადაწერა ზედმეტ ფაილებს არ წაშლის.
2. ძველი პროექტის `.env` გადაიტანე ახალ საქაღალდეში **შენს კომპიუტერზე**. ZIP-ში საიდუმლო `.env` არ არის. ან `.env.example` გადააკოპირე `.env` სახელით და შეავსე.
3. საჭიროა Node.js 22 ან უფრო ახალი. PowerShell ტერმინალი გახსენი ახალი პროექტის საქაღალდეში და გაუშვი:

```powershell
npm ci
npm test
npm run check
```

4. ძველი ბოტის გაშვებული პროცესი გააჩერე; ერთსა და იმავე ტოკენზე ორივე ვერსია ერთდროულად ნუ გაუშვებ. შემდეგ:

```powershell
npm start
```

5. ბრძანებების სიიდან წაშლილი ფუნქციების ასაღებად საჭიროა ბრძანებების თავიდან რეგისტრაცია. ამ ბრძანებას შენ უშვებ შეგნებულად — ის აპლიკაციის გლობალურ ბრძანებებს ამ ვერსიის სიით ანაცვლებს და `GUILD_ID` სერვერის ძველ დუბლიკატებს ასუფთავებს:

```powershell
npm run deploy -- --clear-primary
```

`TOKEN`, `CLIENT_ID`, `GUILD_ID` და ბაზის URI მანამდე სწორად უნდა იყოს შევსებული. მხოლოდ ერთ სერვერზე გამოცდისთვის შეგიძლია `npm run deploy:guild` გამოიყენო, თუმცა ეს არსებული გლობალური ბრძანებების სიას არ ცვლის.

## მონაცემები და გამოქვეყნება

ეს პაკეტი შენს კომპიუტერს, GitHub-ს, Northflank-ს ან Discord-ს ავტომატურად არ ცვლის. არსებული მონაცემები PostgreSQL-შია და ZIP-ში არ ინახება. ბაზაში წაშლილი მოდულების ძველი ცხრილები განზრახ რჩება — მათ აპლიკაცია აღარ იყენებს, მაგრამ ისტორია არ იკარგება. მონაცემების DROP/DELETE გასუფთავება არ ემატება.

პირველ გაშვებაზე არსებული `akane_` ძირითადი ცხრილები საჭიროებისას `kitsune_` სახელებზე გადადის მონაცემების შენარჩუნებით. თუ ორივე სახელით უკვე არსებობს ერთი და იგივე ცხრილი, გაშვება კონფლიქტზე გაჩერდება; მონაცემებს ერთმანეთზე არ გადაწერს. გაშვებამდე შეინარჩუნე ბაზის სარეზერვო ასლი. ტესტი მოიცავს ძველი მომხმარებლის XP/რანკის გადატანას.

თუ Northflank GitHub-იდან აქვეყნებს, Git-ში წაშლილი ფაილებიც უნდა დაფიქსირდეს; მხოლოდ ახალი ფაილების დამატება ძველ მოდულებს ვერ მოხსნის. სერვერის არხები, ძველი პოსტები და როლები ავტომატურად არ იშლება. `/setup` ახალი გზამკვლევების გასაახლებლად გამოიყენე; დარჩენილი ძველი mission/trial/hub პანელები შეგიძლია Discord-ში ხელით წაშალო. მათი ღილაკები ძველ ფუნქციებს ვეღარ გაუშვებს და შესაბამის შეტყობინებას დააბრუნებს.

## შემდეგი განვითარება

1. ცალკე სატესტო სერვერზე შევამოწმოთ მისალმება, Bloxlink ბმულები და setup.
2. შევამოწმოთ ერთი XP ლეველ-აპი, ავტომატური რანკი, staff-ის setrank/removerank და როლების იერარქია.
3. შევამოწმოთ ერთი მოდერაციის მოქმედება და ერთი სრული ტიკეტის ციკლი.
4. ამის შემდეგ დავხვეწოთ ვიზუალი და ტექსტები. დამატებითი სისტემები დავაბრუნოთ მხოლოდ კონკრეტული საჭიროების მიხედვით.

## შემოწმების ფარგლები

`npm test`: ბრძანებების ჩატვირთვა და ფორმატი, წაშლილი მოდულების არქონა, XP საზღვრები/cooldown, გზამკვლევები, ძველი ღილაკები; PGlite-ის დროებით PostgreSQL გარემოში — schema, XP, rollback, Guardian-ის მიერ დაბლოკილი XP, რანკები, განმეორებითი initialization და ძველი მონაცემების მიგრაცია. Discord-ის როლების შეცვლა ტესტში ჩანაცვლებულია; რეალური API და hosted PostgreSQL არ გამოყენებულა. PGlite-ს არ აქვს სესიებს შორის advisory locks, ამიტომ მხოლოდ ეს გამოძახება ტესტში ჩანაცვლებულია.

`npm run check`: JavaScript სინტაქსი, ლოკალური require-ბმულები და 30 slash ბრძანების სერიალიზაცია. მოქმედ Discord სერვერზე end-to-end ტესტი ჯერ არ ჩატარებულა.
